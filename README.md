# Outlier Static Site

The static marketing site for Outlier. `index.html` is hand-written; the ~60 pages
under `seo/` are generated by `_seo_build/scripts/render.py` from CSVs in
`seo/_data/`.

Serve locally with:

```bash
python -m http.server 8000
```

Then open `http://localhost:8000`.

## Deployment — read this before changing anything about hosting

**Since 2026-11-07 (15:28–15:35Z) this site is served by GitHub Pages behind Cloudflare.** Before that it was Porkbun
static hosting (`server: openresty`, `x-service: pixie-sh`), and everything this file used to say about the host
(stale-on-404, deletions that never propagate, path exclusion configured at the host) described Porkbun. It no longer
applies. Ask the server, not this file:

```
$ curl -sI https://outlier.host | grep -i '^server\|^x-github\|^cf-cache'
server: cloudflare
x-github-request-id: …
cf-cache-status: DYNAMIC
$ gh api repos/mattkerr09/outlier-site/pages --jq '{build_type,source,cname}'
{"build_type":"legacy","cname":"outlier.host","source":{"branch":"main","path":"/"}}
```

- **DNS and TLS:** Cloudflare (proxied, SSL Full, Always Use HTTPS). `http://` and `www.` answer 301 to `https://outlier.host/`.
  The rollback is in `~/ops/launch/outlier-dns-rollback.txt` (outside this repo).
- **Build (since 2026-11-07 17:20Z): Pages `build_type` is `workflow`.** `.github/workflows/pages.yml` publishes an
  artifact of the site's files only. It assembles `_site` from `main` without `scripts/`, `_seo_build/`, `seo/_data/`,
  `README.md` and `.github/`, fails if any of those is inside or a key site file is missing, and deploys it with
  `actions/deploy-pages`. It runs after `gates.yml` succeeds on `next` (a push made with `GITHUB_TOKEN` triggers no
  workflow, so it cannot run on push to main); `gh workflow run pages.yml` deploys by hand. Rollback: set `build_type`
  back to `legacy`, which publishes the whole repo again. `.nojekyll` only matters to the legacy build: keep it for that
  rollback.
- **`CNAME`** (`outlier.host`) must stay in the repo root; Pages reads the custom domain from it.
- **URLs** (measured 2026-11-07): a folder without its slash (`/about`) answers 301 to `/about/`; `/thank-you` and
  `/thank-you.html` both answer 200; an unknown path answers 404 with the site's own `404.html`.
- **Headers:** Pages sends `cache-control: max-age=600` and no security headers (no HSTS, CSP or X-Frame-Options).
  Headers can only be added at Cloudflare, not from this repo.
- **Not on this host:** the founding-offer state (`kerr-lead-agent.kerrco.workers.dev/founding`) and checkout
  (`kerr-affiliate-hub`) are Cloudflare Workers. The move did not touch them.

### Deploys go through `next` — push there, never to `main`

Pages builds `main` the moment it moves, so `main` is the gated branch:

1. Push your commits to `next` (`git push origin HEAD:next`, after rebasing onto `origin/main`).
2. `.github/workflows/gates.yml` runs every gate on that exact commit.
3. Only if all of them pass, its last step fast-forwards `main` to that commit; then `pages.yml` publishes the site files from `main`.

A red gate leaves `main` where it was: the site keeps serving the last commit that passed. Fix it on `next` and push
again. If `main` moved some other way, the promote step refuses (not a fast-forward); rebase `next` onto `origin/main`.

The local half is `scripts/githooks/pre-push`, installed per checkout with `git config core.hooksPath scripts/githooks`.
It refuses a direct push to `main`, and runs `claim_freshness_gate` and `faq_schema_visible_gate` on a push to `next`.

**The honest limit.** Nothing on GitHub stops a push to `main`: there is no branch protection. `git push --no-verify`,
or a push from a checkout or a machine without the hook, still reaches `main` and goes live. CI still runs the gates on
such a push and shows red, but after the fact. Closing that needs GitHub branch protection on `main` (with the workflow
allowed to push it), a change to the repository's settings that has not been made.

### How long a change takes to reach a visitor

On Pages: CI on `next` (the gates), then the promote, then a Pages build, then up to 10 minutes of edge cache
(`max-age=600`). Measured on the first push after the move (2026-11-07): pushed to `next` at 16:34:19Z, and a plain GET (no cache-busting) of the changed file showed the new copy within 171 s, polled every 30 s; CI had promoted `main` by the same poll. On Porkbun the same path took 11–12 minutes.

Deletions now propagate: a removed file answers 404 once the cache expires. (On Porkbun they never did, and the rule
was "replace the contents, never `git rm`".)

⚠️ **`67223b34aed54ecb802e8ffcbacb9ec2.txt` must STAY in this repo.** It is a superseded IndexNow key file whose body is
now `revoked`, which is what makes the old key stop validating. It looks like dead weight; it is a live control.

### What is public

Only what `pages.yml` puts in the artifact: the site's pages and assets. `scripts/`, `_seo_build/`, `seo/_data/`, this README
and `.github/` are in the repository but not on outlier.host (measured 2026-11-07: each answers 404). Anything else you commit
at the root or in a page folder IS published, so internal notes still never go in the site's folders; `no_internal_docs_gate`
checks that, and its job did not change. A new internal folder must be added to the workflow's exclude list in the same commit.

## Gates

`scripts/*_gate.py` — ten of them, all run by `.github/workflows/gates.yml`.
They check download URLs against the current release, checkout links, link and
asset resolution, the offline proof and its control, deploy freshness against
HEAD, live-status badges, the word floor, internal docs, unstyled classes.

Note what they do **not** cover: every one reads what a page *says*. None can see
spacing, contrast, rhythm or whether anything renders legibly. Those need eyes and
measured geometry from a real browser.
