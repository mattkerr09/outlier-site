Tabnine now belongs to Tricentis

On July 30, 2026, Tricentis, a software testing company, announced the acquisition of Tabnine. Its press release says Tricentis will integrate Tabnine's Enterprise Context Engine into its Agentic Quality Engineering Platform, to give its testing agents context about a company's code. It does not say what happens to Tabnine's editor plugins, its prices, or any plan for individuals. None of the Tabnine docs pages I read mention Tricentis.

Here is what I could see on 2026-11-02:

  • tabnine.com and tabnine.com/pricing both return an HTTP 301 redirect to tricentis.com. The home page lands on a Tricentis products page. Pricing lands on tricentis.com/contact-us, a contact page headed "Talk with a sales expert" that lists no plans or prices.
  • context.tabnine.com/pricing, the page I used for a price on 2026-10-19, now returns a 404.
  • docs.tabnine.com is still live. Its release notes, subtitled "Tabnine's private installation release notes", run to v6.7.1, with v6.7.0 dated October 21, 2026. The entries are Enterprise features: usage reporting, admin cost controls, a new Agent.
  • On both the VS Code and JetBrains marketplaces, the original Tabnine plugin is marked "(Legacy)" and says Tabnine does not onboard new users to it. The other Tabnine listing in each store is for Enterprise: the VS Code one says it is for Tabnine Enterprise customers only, and the JetBrains one asks for your Tabnine Enterprise Server URL.

A plugin fleet vs a single window

Tabnine ships as plugins for the editors enterprises actually run: VS Code, the JetBrains family, Eclipse, and Visual Studio. Its supported-IDEs page marks VS Code, JetBrains and Eclipse as running on Windows, macOS and Linux, and Visual Studio as Windows only. Admins get a web Admin Console. No standalone desktop app and no mobile app are documented.

The terminal side is in flux. The docs say the original Tabnine CLI is in maintenance mode: since version 6.6 it gets only critical updates through December 31, 2026, and then it is deprecated. Tabnine is moving CLI users to a plugin that bundles OpenCode, launched with the same tabnine command. Both need Agents switched on for your team by an admin.

Outlier is the opposite shape: a native macOS app for Apple Silicon (M1 or later, macOS 15+). No Windows or Linux build, no mobile app, no editor extension: you work in Outlier's own window.

Tabnine rents any model; Outlier ships six

Tabnine is model-agnostic and open about it. Beyond its own proprietary hosted models, its AI models page lists Anthropic Claude (up to Claude 4.8 Opus), OpenAI GPT-5.x, Google Gemini 3.x, and open-weight models such as Qwen3-Coder, Devstral 2 and GLM-4.7. The page says the list changes frequently. Enterprise customers with a private installation can use private model endpoints, and the release notes mention Azure OpenAI and Vertex AI.

Outlier ships six fixed local tiers, Nano 4B up to Plus 397B-a17b. For coding, most people sit on Core 27B: a 15.13 GB download that wants 24 GB of RAM. Six tiers are Apache 2.0 and the weights are published, so you can inspect what you're running.

Here's the honest number. Core 27B measured HumanEval 0.951, and on a blind slice of SWE-bench Verified the general-purpose Core 27B resolved about 45% (18 of 40, older build, 2026-06-25): my own measurement on my own hardware, not a leaderboard submission, and a 40-instance slice is noisy. It sits below the strongest cloud coding agents: if Tabnine hands your hard multi-file refactor to Claude Opus, that's a stronger model than anything fitting in 24 GB of unified memory. Outside code, I also published a separate 54-prompt side-by-side of Core 27B and Claude Opus 4.7, spanning reasoning and knowledge, so you can compare the answers yourself.

Does your code leave the machine?

With Tabnine, yes, by design. The architecture docs describe the plugin querying a remote cluster with the relevant context window, where a GPU-accelerated inference service does the work. The default is Tabnine's own cloud. Some Enterprise customers get a private installation in their own AWS, GCP or Azure account or on-premises, and it can be air-gapped. It runs on Kubernetes. None runs inference on a developer's laptop.

Tabnine's data policy is genuinely strong for a cloud product, and I'll say so plainly. For its own models, the privacy page says it doesn't train on your code, never retains it, and deletes context immediately after the server answers. Its completion model and the "Tabnine Protected" chat model are trained only on permissively licensed open source. But that's a policy, not physics, and telemetry still flows: plugin configuration, machine specs, hashed user identifiers, IDE details and completion counts. I found no opt-out in the docs. The architecture page also warns that third-party models you pick in chat can have different policies. The docs pages I read don't mention Tricentis, so I can't tell you whether any of this changes under the new owner.

Outlier's answer is structural instead of contractual. The model runs on your device: no inference server, no request, and it generates with Wi-Fi off. Nothing to retain. The free Nano and Lite tiers need no account at all.

Where Outlier has no answer

Outlier has no headless CI agent, no admin console, no org policy layer, no repo index, and context bounded by your Mac's memory. If you need agents opening pull requests across forty repos overnight under audited policy, Outlier is the wrong tool.

Where Tabnine genuinely wins

  • Frontier-model quality on demand. Server-side inference means a hard problem can go to a Claude Opus or GPT-5.x class model. That ceiling sits above anything that fits in a laptop's RAM, Core 27B included.
  • It lives where you already work. Inline completion in your editor is less friction than copying code into a separate window, and Tabnine covers enterprise IDEs (Eclipse, Visual Studio) that most AI coding tools ignore.
  • Deployment options a Mac app can't offer an organization. SaaS, customer VPC, on-prem Kubernetes, air-gapped. For a regulated company that must keep everything inside its own perimeter but still wants shared infrastructure, that's rare and real.
  • Governance. Admin Console, admin-chosen models, tool and MCP governance, agent guidelines, usage reporting and monthly Agent budgets. Outlier has none of it, and at 300 engineers that's the difference between adoption and a stalled security review.
  • IP-risk mitigation as a feature. A model trained only on permissively licensed code answers a legal objection that blocks AI adoption outright at some companies. Its docs also describe inference-time protection against license-infringing output, with provenance and attribution. I could not read any indemnification terms, so ask for them in writing.
  • Cross-platform. Windows and Linux developers can use it; Outlier's can't.

Who should pick which

Pick Tabnine if you're buying for a team and have asked Tricentis what happens to your plan; you need completion inside JetBrains, Eclipse, or Visual Studio; you need agents running in CI; you need admin policy and usage controls to clear a security review; you have mixed Windows, Linux, and Mac engineers; or you want frontier-model quality with a written no-train commitment on top.

Pick Outlier if you're an individual developer or a small shop on Apple Silicon; an enterprise platform is out of proportion to your work; or you want a physical guarantee that client code never leaves the laptop rather than a contractual one, at $49 once.

Plenty of people should use both. I run local models for most of my own work and still reach for a frontier model when a problem is genuinely hard. That's not a concession: it's how the tools differ.
