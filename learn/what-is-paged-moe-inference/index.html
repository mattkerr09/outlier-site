What is a paged MoE inference engine

Outlier · published 2026-05-19 Last updated 2026-05-20
Quick answer
  • MoE = only k of N experts active per token (e.g. 10 of 512 in Qwen3.5-397B-A17B).
  • Paged inference keeps active experts in RAM, streams the rest from SSD.
  • Structurally similar to OS virtual memory: bounded working set, on-demand paging.
  • Outlier's V10 engine runs Plus 397B at ~11 GB RAM, ~2.1 tok/s on a 64 GB Mac.

A paged MoE inference engine runs Mixture-of-Experts models without keeping all the weights in memory at once. It uses the property that MoE models only activate a few experts per token, keeps the active ones in RAM, and streams the others from disk on demand. That's how a 397B-parameter model fits on a 64 GB Mac.

What MoE actually is

A standard ("dense") language model passes every token through every parameter. A 70B dense model does 70B parameters' worth of work for each token, no matter what.

A Mixture-of-Experts (MoE) model splits each layer into many small "expert" sub-networks plus a router. For each token, the router picks k experts (typically 2 or 8) out of the total pool, and only those k do work. The rest sit idle for that token.

Qwen3.5-397B-A17B is an MoE: 397B total parameters, 17B active per token. The "A17B" tells you how much compute each token requires (about the same as a 17B dense model). The "397B" is the total knowledge capacity.

The opportunity for paging

If only 17B of 397B parameters are active for any given token, you don't strictly need all 397B in RAM. You need:

  • The shared backbone — attention layers, embedding, the router itself.
  • A cache of recently-used experts, sized to your available RAM.
  • An on-disk store of all experts, available to the cache.

This is structurally the same idea as virtual memory in an operating system: don't keep the whole working set resident, swap in pages on demand. The pages here are entire expert tensor blocks, typically a few hundred MB each.

The engine, step by step

For each generated token:

  1. Embed the new token, run the attention layers (always resident).
  2. Router picks k experts to use for this token's MLP.
  3. For each chosen expert, check the in-RAM cache. Hit → use it. Miss → read it from SSD.
  4. Compute the expert MLPs, combine, produce next-token logits.
  5. Sample the next token, repeat.

The honest performance story: cache hits are fast (it's just a memory access); cache misses are SSD-bandwidth-bound. On a modern Apple Silicon SSD that sustains 5–15 GB/s, a single expert read is a few tens of milliseconds. Over many tokens, hot experts stay cached and the average cost amortizes down.

The numbers, in practice

Outlier's V9 paged engine running Qwen3.5-397B-A17B on a 64 GB Mac Studio M1 Ultra:

  • Peak OS-level RSS: about 11 GB (capacity engine for the same model would need ~209 GB plus headroom)
  • Decode speed: about 2.1 tokens per second
  • SSD read pattern: concurrent pread with queue depth 24, sustained

2.1 tok/s is real. It's slower than the in-RAM capacity engine (which would need 192+ GB of RAM and isn't an option on most consumer hardware). It's faster than not being able to run the model at all.

Where paged MoE wins and loses

Wins:

  • Runs models that wouldn't otherwise fit on your hardware.
  • Memory footprint stays bounded — you can use the rest of the machine.
  • Cache locality means common usage patterns stay fast.

Loses:

  • Cold expert misses are SSD-bound, not memory-bound. First response is slowest.
  • Dense (non-MoE) models can't be paged this way — they actually need all the weights every token.
  • External SSDs over Thunderbolt are half the throughput of internal NVMe, so paging is correspondingly slower.

Why this matters for local AI

Before paged MoE inference, running a flagship-class MoE model locally meant buying a $7,000+ Mac Studio Ultra with 192 GB of unified memory. With paged MoE, the same model runs on a 64 GB Mac Studio that costs about half as much. The architectural specialty is what makes Plus 397B viable for individual developers rather than only well-funded labs.

Frequently asked questions

What is paged MoE inference?

Running a Mixture-of-Experts model by keeping active experts in RAM and streaming the rest from SSD on demand, similar to how an OS pages virtual memory.

Why does paging only work for MoE models?

Because MoE activates just a few experts per token, so most weights can stay on disk. Dense models need all weights every token and can't be paged this way.

How fast is paged MoE inference?

On a 64 GB Mac, Outlier's V10 engine runs Plus 397B at about 2.1 tok/s with roughly 11 GB peak RAM.
