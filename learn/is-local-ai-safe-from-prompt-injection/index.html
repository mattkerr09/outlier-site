Is local AI safe from prompt injection? The honest answer.

Matthew Kerr · Outlier · published 2026-11-20 Last updated 2026-11-20
Quick answer

No. A local model that reads a web page or file can be steered by text inside it, just like a cloud model. Local inference removes the server copy of the chat, but it does not remove prompt injection. Keep web tools off for untrusted work and review what an agent will run before approving it.

A file can contain instructions you did not give

Prompt injection is an attempt to make a model follow instructions hidden in material it was asked to read. For example, imagine asking an agent to summarise a document. A paragraph in that document tells it to ignore your request, read another file and send the contents somewhere else. The paragraph is part of the document, but the model may treat it as an instruction.

That example describes a possible failure, not a measured Outlier incident. The same problem can arise when the model reads a web page or a local file. Putting the model on your Mac changes where the text is processed. It does not stop the model from mistaking someone else's text for your request.

Local inference answers a different question

A local model keeps the processing on your Mac and removes the server copy of that local chat. That helps with where your words go. Prompt injection concerns what the model does after it reads them. An agent with permission to change files or run commands can still propose a harmful step while working locally.

For Outlier, use a local model in Chat or Code mode and turn web tools off when working with untrusted text; Pro can pick Research in Auto mode. Choosing a cloud model with your own API key sends the chat to that provider. Turning web on allows search, web pages and web-connected tools. Connections you set up yourself have their own requests. Read the full network-use list for the built-in checks and optional features.

Use the controls Outlier documents

  • Commands ask first with web off. The privacy page says a command that downloads or installs from the internet “asks you first, every time”. If you approve it, that command can reach the internet. See Agent commands with web off.
  • Review approval before execution. The agent's plan card offers “Approve”, “Approve edited” and “Deny”. The home page states that every plan is reviewable and editable before it runs. See the agent plan-review example.
  • Check permission modes and the audit log. The home page describes “File read/write and shell execution behind permission modes, with a plan-review card, repair loop and audit log.” See Agent tools, with approval. Review the mode you are using before you start a task.

These controls give you places to inspect what the agent wants to do and what it did. They do not establish that a model will reject every hostile instruction. Approval helps only if you understand the proposed action and decide whether it belongs in your task.

Review the action against your original task

Keep web tools off when the work does not need them, especially when reading material from someone you do not trust. This reduces the available network tools. It does not make instructions inside a file harmless, and an approved download command can still use the network.

Read the proposed commands, file paths and destinations. If you asked for a summary, a step that uploads a document or changes an unrelated file needs an explanation. Deny a plan you cannot account for. Ask for a smaller step that you can review before allowing the work to continue.

Keep a separate backup before an agent changes files you care about. Review its results and the audit log after it finishes. A useful local workflow combines keeping the text on the Mac with care over which actions you allow. You can download Outlier and start with a task that uses harmless sample files.
