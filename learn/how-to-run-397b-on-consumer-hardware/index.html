How a 397B model runs on consumer hardware — the architecture

Outlier · published 2026-05-19 Last updated 2026-05-20
Quick answer
  • Four stacked design choices: MoE routing + 4-bit quantization + paged streaming + Apple unified memory.
  • Each step buys ~10× — combined they take 800 GB naive down to 11 GB peak RAM.
  • Apple unified memory removes the PCIe copy step a PC build would need.
  • Result: 397B-parameter MoE model runs on a 64 GB Mac at ~2.1 tok/s.

Running a 397-billion-parameter model on a 64 GB Mac sounds implausible because, in the standard architecture, it is. Four design choices stack together to make it work: MoE routing in the model, 4-bit quantization in the weight format, paged expert streaming in the runtime, and Apple's unified memory in the hardware. Pull any one out and the math stops working.

Choice 1: the model is MoE, not dense

A 397B dense model passes every token through every parameter. For Qwen3.5-397B-A17B (a Mixture-of-Experts model), each token uses 10 of 512 experts at each layer. The "A17B" tells you the active count per token: about 17 billion parameters' worth of compute, even though the total knowledge capacity is 397B.

Without MoE, paged inference doesn't help — a dense model needs all its weights every token, so you can't keep them on disk. MoE is what creates the opportunity to keep most weights idle.

Choice 2: 4-bit quantization

The original Qwen weights are 16-bit floats. At full precision, 397B parameters is about 800 GB on disk and would need similar RAM to load. Quantizing to 4-bit integers (with a small floating-point scaling factor per group of weights) cuts that to about 209 GB.

The quality cost of 4-bit quantization in 2026 is small for well-quantized models. MLX-format 4-bit quantization, which Outlier ships, preserves the underlying model's reasoning quality within rounding noise. The savings are real: 4× smaller on disk, 4× smaller in memory.

Choice 3: paged expert streaming

Even at 209 GB, the model is bigger than a 64 GB Mac's RAM. Paged expert streaming keeps the model's shared backbone resident, plus a bounded cache of recently-used experts, and streams the rest from SSD on demand. The router decides which experts to read for each token; the runtime keeps a queue of concurrent SSD reads to hide latency.

Outlier's V9 paged engine implements this. Measured on M1 Ultra 64 GB: peak OS-level RSS ~11 GB, decode speed ~2.1 tok/s, sustained.

Choice 4: Apple unified memory + fast SSD

The Mac's architecture is unusually well suited to this pattern. Two reasons:

  • Unified memory. The GPU and CPU share the same RAM. When the streaming runtime reads an expert from SSD into a buffer, that buffer is immediately accessible to the GPU for the matmul — no PCIe copy step, no CPU↔GPU memory shuffle. On a PC build with discrete GPUs, you'd add a multi-hundred-millisecond copy cost per expert; the architecture would be roughly 10× slower.
  • Fast on-package SSD. Modern Apple Silicon Macs sustain 5–15 GB/s sequential read off the internal NVMe. That's enough to deliver a few hundred MB of expert weights in the budget needed for ~3 tok/s generation.

This is also why external Thunderbolt SSDs are slower (typically 2–3 GB/s sustained) and why Intel Macs aren't supported — they don't have the unified memory architecture that makes the SSD→GPU path direct.

Each step buys an order of magnitude. The combination is what makes the model viable on hardware most developers can actually own.

The honest tradeoff

This setup is slower than the same model in the cloud on a server with 8 H100 GPUs. Plus 397B at 2.1 tok/s locally vs ~50–80 tok/s on a dedicated server is a real gap. What you trade speed for: no API key, no rate limit, no cloud trip with your code, no recurring bill after the model is on disk. For long-form coding, architecture review, or any task where you can wait, the trade is often worth it.

Frequently asked questions

How does a 397B model fit on a 64 GB Mac?

Four stacked choices: MoE routing, 4-bit quantization, paged expert streaming, and Apple's unified memory. Each cuts the requirement by roughly an order of magnitude.

Why does Apple Silicon help specifically?

Unified memory means SSD-streamed expert weights land directly in GPU-accessible memory with no PCIe copy step, which a PC build would need.

Is it as fast as the cloud?

No. About 2.1 tok/s locally versus 50 to 80 on a dedicated server. You trade speed for privacy, no API key, and no recurring bill.
