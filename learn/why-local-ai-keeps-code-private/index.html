Why local AI keeps your code private

Outlier · last updated 2026-05-19

When you ask a cloud AI tool to refactor a function, your code travels across the internet to a server you don't control, gets processed there, and the response travels back. When you ask a local AI tool to do the same thing, none of that happens. Same workflow, completely different data path. Here's what that actually means for code privacy in practice.

What "your code" means in this context

In an AI coding workflow, "your code" includes more than just the source you pasted. It's typically:

  • The prompt text you typed (which may include credentials, customer names, or business logic).
  • The file contents the agent read while working (which is often most of a feature or module).
  • The shell command output the agent processed (which can include environment variables, log lines, error messages with PII).
  • The conversation history (which the next turn references).

Every cloud call sends some subset of these. Even a tool that "only sends prompts to the cloud" is sending the prompts that contain your code excerpts.

The cloud path

A cloud AI tool's data flow for a single refactor:

  1. You select a function locally.
  2. The tool packages it into a prompt along with project context (often dozens of files).
  3. The prompt is sent over TLS to the provider's API.
  4. The provider's inference server processes it and may log it. Most retain prompts for some period for abuse monitoring, sometimes for training.
  5. The response comes back.
  6. The conversation may be retained on the server for resumption.

Reputable cloud providers (Anthropic, OpenAI) have specific policies about what they do with prompts. Enterprise customers can usually opt out of training. But the data physically traverses someone else's network and lives on their disks for some period. For regulated industries (healthcare, finance, defense, legal) that often makes cloud AI either prohibited or so heavily reviewed that it isn't worth the friction.

The local path

A local AI tool's data flow for the same refactor:

  1. You select a function locally.
  2. The tool packages it into a prompt.
  3. The prompt goes to the local inference runtime running on your Mac.
  4. The model's weights, loaded from your disk, process it in your unified memory.
  5. The response comes back.
  6. The conversation is stored in ~/.outlier/ on your disk.

No external network call. No third party touches the prompt or response. If your Mac is offline, the entire workflow still works.

Where local tools do still talk to networks

Honest list of things local AI tools still touch the internet for, none of which involve your code:

  • Initial model download. First time you use a model, the weights are fetched from HuggingFace. After that, no network is required for inference. Outlier downloads Nano (~3 GB) on first launch and bigger tiers on demand.
  • App updates. The app checks for new versions periodically. You can disable this.
  • Website analytics. Outlier's marketing site uses Plausible (privacy-friendly, no cookies). The app itself doesn't phone home with usage data.
  • Optional connectors. If you opt into a web-search MCP tool, a Slack integration, or any cloud MCP server, those make their own clearly-labeled network calls. Off by default.

The verification test

The cleanest way to verify a local AI tool actually keeps your code local: turn off your Mac's wifi and Bluetooth, then use the tool. Chat should work. Agent should work. File edits should work. Project memory should work. If any of those fail in airplane mode, that piece is calling out to the cloud and you should know exactly which one.

Outlier passes this test. After the first-launch model download, the entire inference + agent + memory workflow runs with the network disabled.

Where this matters most

Two categories of work where local AI is the only viable option:

  • Regulated code. If your contract, customer agreement, or regulator prohibits sending code to a third-party AI provider, local is the only option. This includes most healthcare PHI, financial trading code, defense contractor work, and law-firm document automation.
  • Pre-public IP. Code that hasn't been released yet, algorithms representing a competitive edge, secrets management implementations. Sending these to a cloud AI for "just a quick refactor" is often what the legal team wants you to stop doing.

For developers outside those categories, the local-vs-cloud choice becomes more about insurance: today's cloud provider may change its terms next year. Today's local tool keeps working unchanged.
