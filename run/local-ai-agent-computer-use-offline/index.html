A local AI agent with computer use, fully offline on a Mac

Outlier · last updated 2026-05-19

"Computer use" is the family of AI capabilities where the model sees a screenshot of your desktop, decides what to click or type, and then does it. Anthropic's cloud version is well known. The local version is less well known and trails on a few axes, but it works — here's what that actually looks like on a Mac.

The three primitives

Computer use needs:

  1. Screen perception. A model that can take a screenshot as input and describe or reason about it. For Outlier, this is the Vision 35B-A3B tier — a multimodal MoE that handles image + text.
  2. Action emission. The model produces structured tool calls like "click at (x, y)" or "type 'hello'." Outlier's agent loop accepts these and forwards them to a sandboxed executor.
  3. Action execution. A small driver that actually moves the mouse, presses keys, or types. macOS makes this available through the Accessibility framework; the user has to grant the app Accessibility permission once.

None of those three pieces requires a network call. The screenshot is captured locally, the model runs locally, the actions execute locally.

What Vision 35B sees and decides

Vision 35B is a 35-billion-parameter Mixture-of-Experts model with an image encoder. On a 16 GB MacBook Air, it runs via V10 streaming at about 8 tok/s with ~3.5 GB peak OS-level RSS. On a 64 GB Mac Studio it runs in capacity mode noticeably faster.

For computer-use tasks the model is asked: "Here's a screenshot of my desktop. The user wants to find the export-to-PDF button in this app. Where should I click?" The model returns an annotated answer with rough coordinates or a description of the UI element. The Outlier agent then either clicks, asks for confirmation, or hands control back to you.

Where the local version trails

Honest:

  • Visual reasoning quality. Vision 35B is good but it's smaller than Claude's vision stack. On crowded, low-contrast, or unusual UIs (older Mac apps, dense data tables, custom themes), it makes more mistakes.
  • Latency. Each "look + decide + act" loop is on the order of seconds because the model has to encode the screenshot, reason, and emit the action. The cloud version isn't dramatically faster but the gap is real on long sequences.
  • Tool ergonomics. Outlier's computer-use surface is newer than the chat / agent surfaces. Expect rougher edges and more approval prompts.

What the local version gives back

  • Nothing on screen leaves your machine. Whatever's visible — open emails, password managers, customer data, internal dashboards — stays local. This is the entire point of running computer use locally.
  • No per-action billing. Computer-use cloud APIs charge per screenshot processed. Local has no such meter.
  • Works offline. Useful for on-device automation that needs to keep running without a network — backup workflows, scheduled scripted operations, kiosk-style setups.

How to try it

In the Outlier app, switch to Vision 35B (Standard tier, $149 once includes it). Open the Agent mode. Grant the app Accessibility permission when prompted. Ask the agent something like "open Calculator and compute the square root of 169." The agent takes a screenshot, decides what to do, asks for approval, and acts. The approval gate is on by default for any action with side effects; you can scope-grant it for a single workflow if you want it to run uninterrupted.
