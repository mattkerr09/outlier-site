How to run a 397B-parameter model on a 64 GB Mac Studio

Outlier · published 2026-05-19 Last updated 2026-05-20
Quick answer
  • Qwen3.5-397B-A17B is a 209 GB MoE model at MLX 4-bit.
  • Outlier's V10 paged streaming engine runs it on a 64 GB Mac Studio at ~2.1 tok/s.
  • Peak OS-level RSS during generation is ~11 GB, not 209 GB.
  • Apple Silicon required (M1+); SSD bandwidth is the practical bottleneck.

A 397-billion-parameter model has no business running on a 64 GB Mac. The full Qwen3.5-397B-A17B weights are about 209 GB on disk. By the usual rules of thumb you need a server with hundreds of GB of RAM and at least one big GPU. Outlier ships a streaming inference engine that says: not necessarily.

The naive math

Take the Qwen3.5-397B-A17B model at MLX 4-bit quantization. The HuggingFace repo (mlx-community/Qwen3.5-397B-A17B-4bit) weighs in at ~209 GB. To load every parameter into unified memory at once you need a Mac with at least that much RAM, plus headroom for the KV cache, the activation tensors, and the operating system. In practice that means a 192 GB or 256 GB Mac Studio Ultra — which is a $7,000–$10,000 machine.

On a 64 GB Mac Studio there's no way to hold the whole model resident. The capacity engine (the straight load-everything-into-RAM path) refuses to start. So either you don't run the model, or you change the rules.

Why MoE makes this tractable

Qwen3.5-397B-A17B is a Mixture-of-Experts model. The "397B" is the total parameter count across all experts; the "A17B" is the active count per token. At inference time, for each token, a router picks 10 of 512 experts and only those 10 do work. The other 502 sit idle for that token.

That means at any given moment the model only needs about 17B parameters worth of weights to compute the next token. The rest of the 397B is dormant. The question becomes: can we keep only the experts we need in memory, and stream the rest from SSD on demand?

Paged expert streaming, in plain terms

That's exactly what Outlier's V9 paged engine does. The model's expert tensors stay on disk as memory-mapped safetensors files. When the router picks an expert for a given token, the engine reads only that expert's slice from disk — a few hundred MB at a time — multiplies it through the activations, and lets the OS page it back out.

Concretely on a 64 GB Mac Studio M1 Ultra running Plus 397B in V9 paged inference:

  • Peak OS-level RSS: about 11 GB
  • Generation speed: about 2.1 tokens per second
  • SSD read pressure: noticeable but bounded — concurrent pread with queue depth 24

2.1 tok/s is not fast. The honest comparison is Claude Opus at ~80–100 tok/s in the cloud. But the model is doing real work — every token actually goes through the full 397B routing logic, just with experts streamed on demand instead of all resident.

Hardware floor and tradeoffs

V9 paged inference works because Apple Silicon has fast unified-memory bandwidth and (on M1 Pro/Max/Ultra and newer) NVMe SSDs that sustain several GB/s of sequential read. The minimums Outlier targets for Plus:

  • RAM: 64 GB unified memory. 32 GB doesn't have enough headroom for the active expert set plus the KV cache during long conversations.
  • Storage: 250 GB free for the model download. Outlier downloads the full 209 GB of weights once; streaming is from those local files, not from the network.
  • CPU/GPU: Apple Silicon M1/M2/M3/M4. Intel Macs are not supported by the MLX backend.

The tradeoff against the capacity engine (the all-in-RAM path) is straightforward: V9 paged inference uses ~10× less peak memory but is bound by SSD bandwidth instead of memory bandwidth. On a long context with high cache reuse the gap narrows; on a fresh prompt with cold experts it widens.

When to use it

Plus 397B on the V9 paged engine makes sense when you need the strongest local reasoning the lineup offers and you can wait. Long-form analysis, code review of large diffs, architectural conversations — tasks where a few minutes of generation produces something worth reading. For interactive chat where you want a response in seconds, smaller tiers like Core 27B (20.7 tok/s on M1 Ultra) or Lite 9B (53.4 tok/s) are the right pick. Outlier ships all of them and lets you swap mid-conversation.

Frequently asked questions

Can you really run a 397B model on a 64 GB Mac?

Yes. Outlier's V9 paged engine runs Qwen3.5-397B-A17B on a 64 GB Mac Studio at about 2.1 tokens per second, using roughly 11 GB of peak memory by streaming expert weights from the SSD on demand.

How much disk space does the 397B model need?

About 209 GB for the MLX 4-bit weights. They download once, then inference streams from those local files with no further network use.

Why does a 397B MoE model fit when a 70B dense model might not?

Because a Mixture-of-Experts model activates only a fraction of its parameters per token (17B of 397B here), so the engine keeps active experts in RAM and pages the rest from disk.
