How to run Claude-Code-style agents offline on a Mac

Outlier · published 2026-05-19 Last updated 2026-05-20
Quick answer
  • Claude Code's loop is plan → tool calls → execute → loop; nothing requires cloud.
  • Local version: Core 27B or Code 27B as the model, MCP tools, on-disk memory.
  • Outlier ships this in one app; Claude Desktop + filesystem MCP is another option.
  • Trades ~4× speed feel for offline operation and zero API token cost.

Claude Code is a terminal-resident coding agent that reads your files, edits them, runs shell commands, and asks for approval at the right moments. Its core loop has no requirement to be cloud-hosted. With a local model and the right tooling you can run the same shape of workflow with no network — here's how.

The agent loop, decomposed

A coding agent has three moving pieces:

  1. A model that can produce structured tool calls (read this file, write this diff, run this test).
  2. A tool executor that runs those calls against your filesystem and shell, with appropriate approval gates.
  3. A conversation manager that feeds tool results back to the model and keeps a turn-by-turn log.

Claude Code's cloud version uses Claude Opus 4.7 for piece 1 and a slick terminal UI for pieces 2 and 3. The local version swaps the model for one that runs on your Mac, keeps the tool executor running locally, and lives in a Mac-native UI rather than a terminal.

What you need locally

For piece 1: a model fine-tuned to produce structured tool calls. Outlier's Core 27B and Code 27B do this; pass@1 on HumanEval is 0.8659 — high enough that the model holds its own on real refactors. For piece 2: a sandboxed shell, a filesystem driver, and approval gates. For piece 3: a project-aware UI with persistent chat history. Outlier ships all of this in one app, gated behind MCP (Model Context Protocol) so the tool surface is portable.

Setting it up

  1. Download the Outlier DMG from outlier.host and install.
  2. First-launch downloads Nano 4B as the chat default. For coding, switch to Core 27B (Standard tier) — first use triggers a ~16 GB download.
  3. Open a project folder. The app indexes it (filenames, source structure, optional content embedding).
  4. Switch to "Agent" mode. The model now has tools available — file read, file write, shell, project search, web search if you enabled it. Each first-use of a tool prompts you for approval.

What you see resembles Claude Code: the agent describes a plan, executes it step by step, and reports what happened. The shape of the conversation, the approval gates, the project context — all there.

Where Claude Code still wins

Honest list:

  • Raw model strength. Claude Opus 4.7 is one of the strongest cloud-only models available in 2026. On novel research problems or 50k+ token contexts, it still has a real edge over Core 27B.
  • Throughput. A 5,000-token diff takes ~60s in Claude and ~4 minutes on Core 27B locally. The output ends up the same; the wait is real.
  • Tier swap is free. Claude doesn't physically swap models between requests. Outlier's cold-load on a tier change is ~74s.

On the parity bench (54 head-to-head tests against Claude Opus 4.7 in mid-2026), Outlier scored 98.9% overall and 100% on the 9 hardest additions (chess engine, raft/paxos, ZK proofs, needle-in-context, etc.). For the 95% of coding work where output quality matters more than speed, the local version closes the gap.

Frequently asked questions

Can you run a Claude-Code-style agent offline?

Yes. The plan, act, verify loop runs locally with a model like Core 27B plus MCP tools; no cloud connection is required.

How close is the local experience to Claude Code?

The workflow shape is the same: plan, file edits, approval gates, and project context. The differences are speed and the underlying model's ceiling.

What does the local version give up?

Mainly speed (about 4x slower end to end) and the very top of research-grade reasoning. On common coding tasks the bench parity is 98.9%.
