v1.6 in flight

Inside the app.

Outlier isn't a chat box. It's a Mac-native AI workstation with five modes, an agent harness, and a custom inference engine — all wrapped in a Tauri app under 10 MB. One download, no account, runs forever.

Mode 1

Chat

Standard conversational AI. Pick your tier (Nano for speed, Core for quality), type, get answers. Multi-turn context held locally. File drops accepted. Markdown rendering, code highlighting, copy buttons that work like a Mac app should.

Mode 2

Code

Coding-tuned system prompt, lower temperature, autonomous-mode defaults. Ships Core's weights — Core scored 86.6% HumanEval (verified, n=164) which beat Qwen3-Coder-30B-A3B by 9.15 points in our audit. Same brain, code-tuned config.

Mode 3

Deep Research

Multi-step research mode. The model breaks your question into sub-queries, plans an investigation, reads what you give it (PDFs, docs, links), and writes a structured report. Like Perplexity, but offline and uncapped.

Mode 4

Computer

Agent mode. The model can click, type, and use other Mac apps on your behalf. You approve each plan before it runs. Diffs shown for code edits. Test harness verifies outcomes. The plan-approve-execute-verify loop, locally.

Mode 5

Autonomous

Long-horizon task mode. Give the model a goal, it runs without you watching. Returns when finished or stuck. For coding tasks, large research jobs, batch operations. Pro tier feature.

Engine

V9 Paged

Custom inference engine on top of MLX. Prefix-cache for conversation continuity. Hybrid-attention-aware KV layout. Streams tokens as they generate. Faster than Ollama and LM Studio at the same model size on the same Mac.

What the app actually does

📂 Project folders

Point Outlier at a folder. It indexes the contents (code, docs, PDFs, images for Vision tier) and answers questions with file-level citations. RAG happens entirely on your Mac.

🔍 Web search (opt-in)

Toggle web search on for current info. Always labeled when active. Off by default. Search queries route through your chosen provider — your prompts don't get logged on someone else's AI server.

🔄 Bring your own model

Free tier supports BYOM. Drop in any compatible Hugging Face model — Bonsai, Llama, Mistral, anything that runs through MLX. Outlier becomes the wrapper, you pick the brain.

🔑 Bring your own key

BYOK for cloud APIs too. Wire in your Anthropic, OpenAI, or OpenRouter key. Use Claude Sonnet through Outlier's interface when you want to. Your key, your usage, your bill.

💾 Local chat history

Every conversation saved to a local SQLite database. Search across history, restore old threads, export to markdown. The database file lives in your home directory — yours to back up, delete, or move.

⚡ Tauri-native

Built with Tauri instead of Electron. Under 10 MB installer. Native Mac feel. Real macOS keyboard shortcuts. Universal binary for Apple Silicon. No web wrapper, no Chromium tax.

Transparency

Why "Code" and "Core" share weights

In our Day 30 audit, we ran HumanEval pass@1 on every base model in our planned lineup. The result was unexpected:

Qwen3.6-27B (Core base): 86.59% ±0.027
Qwen3-Coder-30B-A3B (planned Code base): 77.44% ±0.033
Delta: +9.15 pp at 2.18σ — statistically significant

The general-purpose Core base outscored the dedicated coder by 9 points on coding. So we collapsed the Code tier: ship Core's weights with a code-tuned system prompt, lower temperature, and autonomous-mode defaults. Same weights, two product surfaces.

GitHub Copilot does the same thing — it's GPT-4 underneath with a coding-specific wrapper. We do it transparently and tell you why: shipping the better weights under both names is honest engineering, and it saved a Sprint G distillation run we repurposed for the Pro tier.

And one more thing

Local AI is better for the planet.

This isn't a marketing line. The numbers are real, and they're getting worse fast. Every query that runs on your Mac instead of someone's H100 rack is a query that didn't need a gigawatt datacenter.

1,050 TWh

Projected global data center electricity use by end of 2026 — roughly Japan's entire annual consumption.

80–90%

Share of AI energy consumption driven by inference, not training. Every query counts.

~10×

Energy used by a single ChatGPT-style query compared to a standard Google search.

The inference layer is where AI energy demand is exploding. A single question to a cloud model means booting up a GPU rack, streaming the prompt through a network fabric, running it, streaming the answer back. The electricity comes from a grid that's increasingly struggling to keep up. Virginia's data centers already consume more than a quarter of the state's electricity. Ireland's are projected to hit 32% of national consumption by end of 2026.

Apple Silicon does the same work on a fraction of the power. Unified memory means no PCIe transfers, no NVLink fabric, no cooling towers. An M-series Mac running a 9B model draws about as much electricity as a laptop charger. The same Core tier that runs at 0.85 MMLU on 17 GB of unified memory would require an 80 GB H100 to run unquantized. The H100 pulls 700 watts. Your Mac pulls 30.

Is Outlier going to single-handedly fix the climate impact of AI? No. But if most inference shifts to the edge — where the chips are already efficient and already running — the trend line bends. That's the argument. It's real, and it's the one part of this whole thing that isn't about software.

How we measure

Numbers with a paper trail.

AI startups quote benchmarks the way restaurants quote calorie counts — confidently, with no audit. We treat unprovenanced numbers as unverified. Every metric on this page lives with five fields: source file, command, sample size, standard error, date measured.

📁 Source file

Every benchmark traces back to a JSON eval result file checked into our sprint logs. If a number on this page can't point to a file, the number doesn't go on this page.

⌨️ Exact command

We log the lm-evaluation-harness command line that produced each number. Including version (v0.4.9.1), shot count (5-shot), batch size, dtype, device. Reproducible runs.

🔢 Sample size

MMLU at n=14,042 (full set). HumanEval at n=164 (full set). No --limit 10 smoke tests promoted to "verified." We learned that one the hard way on Day 9 — never again.

📊 Standard error

Every benchmark on this page includes σ. MMLU stderr ≈ 0.003. HumanEval stderr ≈ 0.027. Lifts reported with the σ-significance they actually clear (Nano +1.87pp at 3.54σ; Lite +1.10pp at 2.22σ).

📅 Date measured

Every number stamped with the date it was produced. Numbers older than 7 days flagged for re-verification before going on marketing copy.

🚫 What we won't claim

Projections that haven't been measured. Smoke tests promoted to "verified." Numbers from training logs that haven't been independently re-evaluated. Vendor benchmarks we haven't reproduced. No marketing department exists to fudge any of this.

Questions

Before you sign up.

When can I actually download the app?
v1.6 is in final testing. Apple Developer ID was approved April 21, 2026 — we're going through Apple notarization now so the DMG lands signed and clean on every Mac. Join the waitlist and we'll email you the moment the public download is live. Founders get the signed DMG before public launch; Contributor / Backer / Patron tiers get beta access during testing.
Is it really free? What's the catch?
No catch. Free tier (Nano + Lite, no agent harness, 100 messages/day cap) stays free forever. Base model weights are Apache 2.0 (Qwen team at Alibaba). Pro tier unlocks all five models, agent harness (Computer + Autonomous modes), and unlimited use. Cancel a Pro subscription and the free tier you downloaded keeps working unchanged.
Why does Code share weights with Core?
Because in our Day 30 audit, the Core base (Qwen3.6-27B) scored 86.6% on HumanEval pass@1 while the dedicated coder (Qwen3-Coder-30B-A3B) scored 77.4%. The general-purpose base beat the specialized coder by 9.15 points at 2.18σ — statistically significant. So we ship Core's weights as the Code product surface, with code-tuned system prompt and lower temperature defaults. Same brain, coding-optimized config. GitHub Copilot does the same thing under the hood — it's GPT-4 with a coding wrapper. We do it transparently.
What's the Pro tier? When does it ship?
The Pro tier is what Founders unlock. It's a bigger, flagship-distilled model (Qwen3.5-397B teacher path or DeepSeek V4 logit distillation) targeting Claude Sonnet 4.6 parity by end of 2026. Currently in Sprint G v3 — held up briefly on host-RAM infrastructure that we'll resolve with vLLM GPU-direct loading or a bigger cluster. No timeline, because timelines are lies. Funded by Founders revenue. Founders get it free when it ships. Pro subscribers ($20/mo or $192/yr) get it automatically too.
Why $200 for Founders? What happens after 250 sell out?
Founders is a one-time $200 payment, lifetime-locked. The 250-seat cap is hard — after it fills, Founders closes and support becomes Pro at $20/month. Founders also get the signed DMG before public launch — that's the early-access benefit while the app is pre-release. $200 ≈ one year of Claude Pro, one tenth of one year of Claude Code. Pricing this way rewards early supporters and gives us a real funded runway for the training runs that build the Pro tier.
What Mac do I need?
Any Apple Silicon Mac (M1 / M2 / M3 / M4) running macOS 13 or later. Nano runs on 8 GB. Lite needs 16 GB. Core needs 16-18 GB tight or 32 GB comfortably. Vision needs 24-32 GB+. Full lineup with V9 paged engine wants 64 GB Mac Studio. Intel Macs are not supported — Apple Silicon only. See the Hardware fit table for specifics.
How does it compare to Ollama or LM Studio?
Ollama is a CLI for developers that recently added a paid cloud tier. LM Studio is a generalist GUI built on Electron. Outlier is Mac-native Tauri (under 10 MB vs ~200 MB), curated tiers instead of a model zoo, strictly local, and staying free at the base tier. All three use similar backends — the difference is polish, curation, the agent harness, and the direction of travel. We're pointed at Phase 4 (Outlier-native flagship). They aren't.
Why is Core slower than the old Compact tier?
v1.5 shipped Compact as Qwen2.5-14B at ~40 tok/s on M1 Ultra. v1.6 ships Core as Qwen3.6-27B at ~21 tok/s. Roughly half the speed because it's roughly twice the parameters. In exchange you get +20 points HumanEval (67% → 87%) and +10 points MMLU (75% → 85%). Core is a bigger, smarter model on the same hardware. 21 tok/s is faster than typing. For most workflows, quality matters more than raw speed past a reading-speed threshold. Long-context performance on hybrid attention layers also improves more than the steady-state bench suggests.
Does my data really stay on my Mac?
Yes. All inference runs on your Mac's GPU via MLX. Prompts, context, and outputs never leave the machine. Web search will be opt-in and labeled when in use. Chat history stored in a local SQLite database in your home directory. Unplug the ethernet and airplane-mode the Wi-Fi — Outlier keeps working.
Is local AI actually better for the environment?
Yes, and the numbers back it up. Inference drives 80–90% of AI energy consumption. Cloud inference means running GPU racks, network fabric, and cooling. Local inference on Apple Silicon uses a fraction of the power because unified memory eliminates most of that overhead. Won't fix climate single-handedly, but every query that runs on your Mac is one that didn't need a datacenter. See the Energy section for sources.
What is Vision tier good for?
Image understanding, OCR, screenshot questions, chart reading, document images. Built on Qwen3.6-35B-A3B with multimodal capability preserved (vision encoder kept on this tier). Vision tier is NOT optimized for code generation — its base scored 0.61 HumanEval vs Core's 0.87. For coding workflows, use Core or Code. For everything image-related, Vision is the tier.
Can I bring my own model? My own API key?
Yes to both. Free tier supports BYOM (drop in any compatible Hugging Face model — Bonsai, Llama, Mistral, anything that runs through MLX). Free tier also supports BYOK (bring your Anthropic, OpenAI, or OpenRouter key) — Outlier becomes the interface, you pay your own provider. Pro modes (Computer, Autonomous) are built around our own models and don't run on BYOM/BYOK by default.
What's the deal with the patents?
Three U.S. provisional patents filed (April 2026), 61 claims across the three applications. Cover the ternary MoE substrate (#64/026,886), substrate-shared speculative decoding (#64/030,368), and per-expert per-channel scale + alpha overlay training method (#64/034,028). Non-provisional deadline April 3, 2027. Patents are a nice-to-have, not the moat. The moat is execution speed plus community plus revenue. We track them transparently because they signal investor credibility, not because they're load-bearing.
Who built this?
Matt Kerr, solo. Kerr & Company LLC (DBA Outlier), Grand Rapids, MI. Built in 30 days on a Mac Studio with about $1,280 in total compute spend. Three U.S. provisional patents on the architecture. Direct line: matt@outlier.host.
What happens when a better open model drops?
We rebase. Our pipeline absorbs the next Qwen, Llama, DeepSeek, or anyone else's release in 1-2 weeks of work. The free tier gets updated open-weights models as they ship — continuously. When Qwen 4 drops, Outlier 1.7 ships with new bases. You don't retrain anything on your end. Just download the update.
