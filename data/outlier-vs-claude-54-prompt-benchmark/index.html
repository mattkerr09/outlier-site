Outlier vs Claude Opus 4.7 — a 54-prompt head-to-head benchmark

Outlier · last updated May 20, 2026

Quick answer

  • 54 prompts run through both Outlier (Core 27B, local Mac) and Claude Opus 4.7 (cloud).
  • Six tests captured side-by-side, raw outputs saved to /private/tmp/parity/*.txt.
  • Reasoning answer (two trains meeting): identical — both 9:17 PM, ~483 mi east.
  • Latest rubric pass rate: 99.5% (53/54 tests at 100%, one writing test at 74.1%).

In May 2026 the same 54 prompts were sent through Outlier (Core 27B, running locally on a Mac Studio M1 Ultra 64 GB) and Claude Opus 4.7 (cloud, via the Claude app). Six of the prompts were captured side-by-side with both responses saved to disk for direct comparison; the full 54 were scored against a flagship-quality rubric. This page is the raw record — what was asked, what was returned, how it was graded, and how to reproduce it on your own Mac.

What was measured (and what was NOT)

Two complementary measurements run in parallel here. Both honest about their bounds:

  • Six side-by-side outputs (the head-to-head). The same prompt fired in both apps in the same week. Both responses saved to /private/tmp/parity/<test>_claude.txt and <test>_outlier.txt. Graded by manual diff: did each model produce a correct, complete, idiomatic answer?
  • 54-test flagship-quality rubric (the parity bench). Outlier's responses scored against must_have and must_not_have keyword regex (e.g., a pomodoro app must include setInterval, AudioContext, localStorage, Notification, keyboard shortcut handlers). The rubric encodes features observed in flagship-app outputs from Claude / ChatGPT / Perplexity. This does not call Claude's API live — it scores Outlier against a checklist of what a flagship answer would contain.

So: head-to-head is "did both produce the same answer." Rubric is "did Outlier produce the kind of answer a flagship model would." Both data sources matter; both have limits.

Methodology — head-to-head (n=6, 2026-05-17)

Each prompt was typed verbatim into both Outlier and Claude on the same Mac, within the same week, on default settings. Responses were copied directly from each app into /private/tmp/parity/<test>_<app>.txt. No editing, no retry-until-good, no cherry-picking — first response from each.

  • Outlier model: Core 27B, 4-bit MLX quantization, default decoding
  • Claude model: Opus 4.7, default settings in the Claude app
  • Hardware: Mac Studio M1 Ultra, 64 GB unified memory, macOS 25.3
  • Date: 2026-05-17
  • Cherry-picking control: first response from each app, no retries

3. Writing — 170-word product blurb for an insulated bottle

Both hit exactly 170 words. Different voices.

Verdict: Both shippable copy. Claude concrete and spec-driven; Outlier lyrical. A copy editor would publish either.

5. Refactor — Python, sum of squares of even numbers

Both produced essentially the same one-liner:

# Claude
from collections.abc import Iterable

def sum_of_even_squares(numbers: Iterable[int]) -> int:
    """Return the sum of the squares of the even numbers."""
    return sum(n * n for n in numbers if n % 2 == 0)

# Outlier
def sum_of_even_squares(numbers):
    return sum(n ** 2 for n in numbers if n % 2 == 0)

Verdict: Same idea, same correctness. Claude adds type hints + Iterable import + docstring.

6. Knowledge — explain the transformer architecture

Both correctly cover attention, multi-head, positional encoding, residual stream, layer norm, feed-forward block. Both note quadratic attention cost. Both name encoder/decoder vs decoder-only variants. Outlier's response is slightly more concise; Claude's includes a worked example of attention computation.

Verdict: Both correct, both complete for an explainer answer.

Methodology — 54-test flagship-quality rubric

The full 54-test rubric (parity_bench/tests.json, 4,106 positive-weight points) fires each prompt through Outlier's POST /chat endpoint and scores the response against per-test must_have and must_not_have keyword regex. Examples:

  • code_pomodoro requires: setInterval, AudioContext, localStorage, Notification, data-theme, aria-, keydown
  • writing_cold_email requires: specific subject line, opening hook, CTA, signature
  • knowledge_async requires: microtask/macrotask distinction, event-loop interaction, code example
  • All tests: must_not_have reasoning leaks (<think>, "Thinking Process:")

The trajectory — 9.2% to 99.5%

The bench has 21 runs in its history file (parity_bench/outputs/history.jsonl). The first run scored 9.2%. Each iteration of the build loop fixed gaps found by the rubric (missing accessibility on a code app, missing CTA on a cold email, reasoning leak in a knowledge response). Most recent 10 runs:

96.9 → 97.1 → 98.9 → 98.9 → 98.9 → 99.4 → 99.6 → 99.8 → 99.5 → 99.5

Latest: 53 of 54 tests at 100%. The one outlier is writing_cold_email at 74.1% — output is good copy, just missed 2 rubric keywords (specific subject-line pattern + signature format).

Reproduce this yourself

The bench is open. Clone, run, compare numbers:

cd /Users/<you>/Documents/Outlier/parity_bench
./run_bench.sh
# ~60 minutes serial on M1 Ultra
# results in outputs/last_run.log + last_score.json
# 21 prior runs in outputs/history.jsonl

Requirements: Outlier app installed (any v1.11.x), backend running on default port. The bench checks http://127.0.0.1:8766/health before each test.

What this benchmark does NOT prove

  • This is not a live Claude API comparison. The 54-test rubric scores Outlier against a checklist of what flagship answers look like — it does not poll Claude for each test.
  • The 6 head-to-head outputs are a small sample, not a statistically powered comparison.
  • The bench measures feature coverage, not benchmark scores on standard suites (MMLU, HumanEval, GSM8K). For those, see the Outlier model cards on HuggingFace — Core 27B: MMLU 0.8511 ± 0.0030, HumanEval 0.8659 ± 0.0267 (best in lineup).
  • Outputs from any LLM are non-deterministic; rubric pass rates may vary ±1-2% across runs even at fixed seed.
